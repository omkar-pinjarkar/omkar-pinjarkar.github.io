TROUBLESHOOTING LABS

Practice
Under Pressure.

Hands-on troubleshooting practice used to build a repeatable investigation habit. These are practice environments, not production incidents.

01

Jenkins Agent Offline

DevOps troubleshooting lab

Problem Agent is unavailable to the controller.

Investigation Check SSH authentication, agent configuration and connectivity.

Verification Confirm the connection path and agent setup.

Resolution Reconnect the node after the access and configuration checks.

Lesson learned: isolate access, configuration and connectivity separately.
02

Docker Permission Denied

DevOps troubleshooting lab

Problem A user cannot interact with Docker.

Investigation Check the Docker socket, user/group permissions and service status.

Verification Confirm the service is available and the user has the expected access.

Resolution Correct the local permission or service issue and verify access again.

Lesson learned: distinguish service availability from user permissions.
03

Kubernetes Troubleshooting

DevOps troubleshooting lab

Problem A workload is not behaving as expected.

Investigation Inspect pod status, events, logs and deployment configuration.

Verification Confirm the workload state and deployment configuration after the check.

Resolution Follow the evidence from workload state to configuration, then verify the deployment.

Lesson learned: use cluster state and events before changing resources.
04

AWS Connectivity Troubleshooting

DevOps troubleshooting lab

Problem A resource cannot reach the expected network destination.

Investigation Trace subnet configuration, route tables, security groups, Internet Gateway and NAT Gateway.

Verification Re-check the traffic path after inspecting each network boundary.

Resolution Correct the network boundary that blocks the path and re-check connectivity.

Lesson learned: trace traffic hop by hop through the architecture.
